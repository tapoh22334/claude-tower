# Claude セッションの中から Tower を操作する — 分節

feature-id: 001-tower-session-cli
由来: value/001-tower-session-cli/orient.md

> 適用範囲は**利用者との境界面**。内部設計は対象外(構築層の仕事)。

## 境界面の要素

利用者は 2 種類いる: セッションの中にいる iwase と、その中で `tower` を呼ぶ
Claude(スキル経由)。どちらも触れる面は CLI の入出力と Navigator の見え方。

| ID | 要素 | 説明 |
|---|---|---|
| E-001 | `tower rename <name>` | 現在のセッションの Navigator 表示名を付け替える |
| E-002 | 対象の既定 = 今いるセッション | Tower の pane の中から呼ぶと、引数なしで自分のセッションが対象になる。`--session <id>` で明示もできる |
| E-003 | 名前の即時反映 | rename 後、Navigator を開き直さなくても次の再描画で新しい名前が出る |
| E-004 | `tower rename --clear` | 付けた名前を外し、最初のプロンプト由来の表示に戻す |
| E-005 | `tower open <dir>` | 既存ディレクトリで新しいセッションを始め、Navigator の選択をそこに移す |
| E-006 | `--prompt <text>` / `--prompt-file <path\|->` | 新セッションの最初のプロンプトとして文字列を渡す(引き継ぎ) |
| E-007 | Navigator の view が新セッションに切り替わる | open 直後、右 pane に新セッションが映る |
| E-008 | `tower project new <name> [--in <parent>]` | ディレクトリ作成 + `git init` + 最初のセッション開始。既定の親は `~/working` |
| E-009 | `tower project add <dir>` | 既存ディレクトリを登録する別名 |
| E-010 | 機械可読な出力 | 成功時に `tower_<uuid>` を stdout に 1 行で出す(スキルが次の操作に使う) |
| E-011 | 失敗時の文言 | ディレクトリが無い / Tower の外から `--session` なしで rename / 名前が空 / プロジェクトが既にある、を区別して伝える |
| E-012 | スキル `skills/tower` | Claude が「名前を変えて」「○○で続けて」「新しいプロジェクトを始めて」を `tower` の呼び出しに写す手順と、引き継ぎ要約の書き方 |
| E-013 | `tower help` の記載 | 3 コマンドが help に載る |
| E-014 | 非対話で完走する | スキルから呼ぶとき y/N の確認で止まらない(tty が無ければ確認を出さない) |
| E-015 | 新セッション行の座席 | open/project new で作った行が、次の再構築でそのプロジェクトのグループに現れる |

|---|---|---|
| E-001 | 残る | 名前は人の意図。自動推定しても「今の作業」を言い当てる保証は無い |
| E-002 | 残る | 「自分」を言わずに済むのは意図の表現として本質 |
| E-003 | 残らない | 完全技術なら表示は常に真実。再描画周期(2 秒)は実装の都合 |
| E-004 | 残る | 「付けた名前を捨てる」は意図 |
| E-005 | 残る | 「あのプロジェクトで続ける」は意図 |
| E-006 | 残る | 何を引き継ぐかは人(または元セッションの Claude)が決める |
| E-007 | 残らない | 完全技術なら「移った」時点で見えている。view の切り替えは Navigator の構造への回避策 |
| E-008 | 残る | 新しい場所を作る意図 |
| E-009 | 残らない | `open <dir>` と同じ結果。語彙の重複 |
| E-010 | 残らない | 完全技術なら呼び出し側は結果を直接知っている。プロセス境界の回避策 |
| E-011 | 残る | 失敗は完全技術でも起きる(無いディレクトリは無い) |
| E-012 | 残る | 意図→操作の写像そのもの |
| E-013 | 残らない | 完全技術なら発見可能性は別の形で満たされる。慣習 |
| E-014 | 残らない | 確認プロンプト自体が破壊操作への回避策で、非対話はその回避策の回避策 |

## 第2段: 文脈と不適合から本体を定義

### misfit 列挙(際立つ順)

1. **セッションの中にいる人が Tower に何も言えない** — Navigator は外から眺める道具で、作業の現場(セッション内)から意図を伝える口が無い。応える要素: E-002, E-001, E-005, E-008
2. **文脈の引き継ぎが手作業の貼り直し** — 移動のたびに要約を書いて貼る。応える要素: E-006
3. **行の名前が過去を指し続ける** — 使い回したセッションほど名前と中身が離れる。応える要素: E-001, E-004
4. **プロジェクト開始の手順が散っている** — mkdir / git init / 登録が別の場所。応える要素: E-008
5. **Claude が代理で操作できない** — 人が覚えて打つしかない。応える要素: E-012, E-010, E-014

### breakdown の想像

| ID | これが壊れたとき、利用者は何に気づくか |
|---|---|
| E-001 | 名前を変えたのに Navigator の行が古いまま。「効いていない」と感じ、二度と使わない |
| E-002 | 「自分の id は何だっけ」と調べる作業が入り、Navigator に戻るのと手間が変わらない |
| E-005 | 新セッションはできたが、別のディレクトリで始まっている。間違いに気づくのは `pwd` を見たとき |
| E-006 | 新セッションが空で始まり、結局要約を貼り直す。機能を使う理由が消える |
| E-007 | コマンドは成功したが画面は元のセッションのまま。「どこに行った?」と Navigator を開く |
| E-008 | ディレクトリはできたが git が無い、またはセッションが始まっていない。残りを手でやる |
| E-010 | スキルが次に何をすればいいか分からず、人に id を聞く |
| E-011 | 「エラー」とだけ出て、ディレクトリの打ち間違いか Tower の外にいるのか分からない |
| E-012 | コマンドはあるが Claude が知らない。人が毎回コマンドを打つ |
| E-014 | スキルの実行が `[y/N]` で止まり、Claude がハングしたように見える |

### purpose / operational principle

| ID | purpose(何のため) | operational principle(どう働いて目的を果たすか) |
|---|---|---|
| E-001 | 行の名前を作業の実態に合わせる | metadata の `session_name` を書き換え、Navigator がそれを優先表示する |
| E-002 | 「自分」を指す手間を無くす | `TMUX` 環境変数から今いる tower セッションを特定する |
| E-005 | 作業の場所を移す | 指定ディレクトリで新セッションを起動し、Navigator の選択を移す |
| E-006 | 文脈を落とさず移す | 渡された文字列を claude の初回プロンプトとして起動する |
| E-008 | 新しい場所を一撃で作る | mkdir → git init → E-005 と同じ経路でセッション開始 |
| E-010 | 連鎖操作を可能にする | 成功時に id を stdout、人向け文言は stderr |
| E-011 | 失敗の原因を取り違えない | 原因別の文言と終了コード |
| E-012 | 意図を操作に写す | トリガー語 → コマンド、引き継ぎ要約の型 |

## 第4段: 関節で切る

### 変わりやすい設計判断

1. **「自分」の特定方法**(`TMUX` 環境変数 → 将来は claude の session id からの逆引きになるかもしれない)
2. **引き継ぎの渡し方**(初回プロンプト引数 → 将来はファイルや `--resume` 連携になるかもしれない)
3. **プロジェクトの作り方**(`git init` だけ → テンプレートや GitHub 作成が増えるかもしれない)
4. **Navigator への通知方法**(状態ファイル + 再構築 → 将来は明示的なシグナルになるかもしれない)

### 切断の妥当性

| 切断面 | 自然な関節か | 根拠 |
|---|---|---|
| 「対象セッションの解決」(E-002)と「名前の書き込み」(E-001) | 関節 | 解決方法が変わっても書き込みは変わらない |
| 「セッション起動」(E-005)と「初回プロンプトの受け渡し」(E-006) | 関節 | プロンプト無しでも起動は成立する |
| 「ディレクトリ準備」(E-008 の mkdir/git init)と「セッション開始」(E-005) | 関節 | project new = 準備 + open。準備の中身が変わっても open は不変 |
| 「CLI」と「スキル」(E-012) | 関節 | スキルは CLI の利用者。CLI の契約(E-010, E-011, E-014)が境界 |
| 「Navigator の選択移動」と「view の切り替え」(E-007) | 関節 | 選択は状態ファイル、view は Navigator 内部の反応 |

三分: core = E-001, E-002, E-005, E-006, E-008, E-012 / supporting = E-010, E-011, E-014 /
generic = E-003, E-004, E-007, E-013, E-015 / omittable = E-009

| E-001 | 強める | misfit 3(名前が過去を指す)への直接の答え。中心そのもの | 導入後 2 週間で rename が使われない、または rename 後も中身を開いて確認している |
| E-002 | 強める | 「自分」を省けることが「セッションの中から」という misfit 1 への答えそのもの | スキルや利用者が結局 `--session` を毎回付けている |
| E-003 | 強める(弱く) | 反映が遅いと「効かない」と誤認して E-001 が使われなくなる | rename 直後に Navigator を見た利用者が「変わっていない」と報告する |
| E-004 | 強める(弱く) | 名前を試して戻せる安心が rename の利用を増やす | 導入後 1 か月で一度も使われない → generic に落として実装は残す |
| E-005 | 強める | misfit 1 と 4 の両方に必要。E-006/E-008 の土台 | open の呼び出しが Navigator の `N` より少ない(摩擦が減っていない) |

| E-008 | 強める | misfit 4(手順が散っている)への答え。E-005 の上に乗る | project new で作った repo をシェルで作り直している |
| E-009 | 強めない | 語彙が増えるだけで新しい意図を表さない | 利用者が `open` を「既存を登録する」行為と結び付けられない |
| E-010 | 強める | スキルが rename → open を連鎖できる | スキルが stdout の id を一度も使わない |
| E-011 | 強める | 失敗の原因が分からない機能は使われなくなる | 失敗時の問い合わせが文言で解決しない |
| E-012 | 強める | 「チャットの中から」という価値の半分はここ。CLI だけでは人が打つ | 利用者が Claude に頼まず自分で `tower` を打っている |
| E-013 | 強めない(中立) | 利用者は 1 人でスキルが手順を知っている。慣習として揃えるだけ | help を見て初めてコマンドを知る場面が起きる → supporting に格上げ |

### misfit 検証(収束だけでは合格にしない)

| ID | 欠けたときに起きる具体的な破綻 |
|---|---|
| E-001 | 使い回したセッションの行名が最初の指示のままで、利用者は目的の行を探すのに 1 行ずつ中を開く |
| E-002 | 利用者(または Claude)は `tower list` で自分の id を探してから打つ。Navigator に戻って `n` を押すのと手数が変わらず、機能は使われない |

| E-012 | Claude に「この名前にして」と言っても何も起きず、人がコマンドを覚えて打つ。「チャットの中から」という価値が消える |
