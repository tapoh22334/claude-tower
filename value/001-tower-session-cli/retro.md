## 6. 欠陥クラスの更新

この repo には `defect-classes.jsonl` が無い。harness.md の DEF-T1〜T7 に追記:

- **DEF-T5 の追記**: 「外部プロセス(CLI)が共有状態を書く」ケース。Navigator 内の
  書き手は楽観挿入で行を先に座らせるが、外部の書き手はそうしない。resync は
  未一覧 id を区別しなければならない(nav-loop.sh の `_session_listed`)。
- **新規 DEF-T8 候補**: 「CLI が成功を返すが pane 側で失敗する」(空の位置引数、
  argument list too long)。pane で起きる失敗は誰も見ていないので、CLI 側で
  断る。検知工程: 単体テスト(境界値)。

## 7. パイプライン自体への改善

- `generate-trace.py` の引数は `<value dir>` 1 つ。vf-pipeline の SKILL.md は
  `<project> <feature-id>` と書いており食い違う(usage が trace.md に入った)。
  → skill-improver の対象(vf-trace の記述を直す)。
- vf-construct の `scripts/`・`adapters/`・`references/construction-contract.md`
  がこの環境に無い。native で回せたが、`verify-contract.sh` が無いので
  GATE-contract は手動になった。→ 同上。
- `check-coverage.py` の失敗経路判定はシナリオ名のキーワード一致。異常系を
  別フロー(UF-006)にまとめると中核フローが「失敗経路なし」になる。今回は
  タグを付け替えて解消したが、「失敗経路は失敗元の中核フローに付ける」を
  vf-acceptance の手順に明記したい。
