# Claude セッションの中から Tower を操作する — ユーザフロー

feature-id: 001-tower-session-cli

> 1フロー = 利用者がひとつの目的を達成する、開始から完了までの一連の操作。

## 利用者型

| 型 | 特徴 | 該当フロー |
|---|---|---|
| セッション内の iwase | Tower の pane の中で Claude と作業中。Navigator は開いていないことが多い | UF-001-001, 003, 004 |
| 代理の Claude(スキル経由) | 利用者の一言を `tower` の呼び出しに写す。対話的確認には答えられない | UF-001-005 |
| Tower の外の iwase | 通常のシェルから `tower` を叩く(Navigator を開いているかもしれない) | UF-001-002, 006 |

## フロー

UF-001-001: 使い回しているセッションの名前を今の作業に合わせる
  利用者型 : セッション内の iwase
  前提     : Tower のセッション `tower_A` の pane の中。Navigator は別 pane で動作中。行名は最初のプロンプト由来
  経路     :
    1. `tower rename "payments 移行"` を実行する(セッション指定なし)
    2. 標準出力に `tower_A` が 1 行出る
    3. Navigator の次回再構築(数秒以内)で行名が `payments 移行` になる
  完了     : Navigator の `tower_A` の行が新しい名前で表示されている
  得る価値 : Navigator を開いたとき名前だけで目的の行を選べる
  関連要求 : REQ-001-001, REQ-001-002, REQ-001-003, REQ-001-005, REQ-001-013
  検証区分 : 機械判定可
  優先度   : 中核

UF-001-002: 付けた名前を外して元の表示に戻す
  利用者型 : Tower の外の iwase
  前提     : `tower_A` に `session_name` が付いている
  経路     :
    1. `tower rename --clear --session tower_A` を実行する
    2. `tower_A` が標準出力に出る
  完了     : metadata に `session_name` が無く、行名が最初のプロンプト由来に戻る
  得る価値 : 試しに付けた名前を捨てられる
  関連要求 : REQ-001-004, REQ-001-013
  検証区分 : 機械判定可
  優先度   : 周辺

UF-001-003: home で出たアイデアを特定プロジェクトの新セッションで続ける
  利用者型 : セッション内の iwase(要約は Claude が書く)
  前提     : `~` のセッション `tower_H` の中。目的のプロジェクト `~/working/foo` は存在する。Navigator は動作中
  経路     :
    1. 要約をファイル(またはパイプ)に用意する
    2. `tower open ~/working/foo --prompt-file -` に要約を流し込む
    3. 標準出力に新セッション `tower_B` が出る
    4. Navigator の選択が `tower_B` に移り、view pane に `tower_B` が映る
    5. `tower_B` の claude は要約を最初のプロンプトとして受け取って動き出す
  完了     : `tower_B` が `~/working/foo` で動作し、Navigator の選択がそこにあり、`tower_H` は変わらず残っている
  得る価値 : 要約の貼り直しがゼロになり、文脈が落ちない
  関連要求 : REQ-001-006, REQ-001-007, REQ-001-008, REQ-001-009, REQ-001-010, REQ-001-013, REQ-001-028
  検証区分 : 機械判定可
  優先度   : 中核

UF-001-004: 新しいプロジェクトを 1 コマンドで始める
  利用者型 : セッション内の iwase
  前提     : `~/working/bar` は存在しない
  経路     :
    1. `tower project new bar --prompt "bar の初期設計を始める"` を実行する
    2. `~/working/bar` が作られ `git init` される
    3. そこで新セッション `tower_C` が始まり、標準出力に `tower_C` が出る
    4. Navigator に `bar` グループが現れ、`tower_C` の行がその中にある
  完了     : ディレクトリ・`.git`・セッション・metadata(`launch_dir`)が揃っている
  得る価値 : 手順を覚えずにプロジェクトを始められる
  関連要求 : REQ-001-011, REQ-001-012, REQ-001-013
  検証区分 : 機械判定可
  優先度   : 中核

UF-001-005: 利用者の一言を Claude が tower の操作に写す
  利用者型 : 代理の Claude
  前提     : Claude は Tower の pane の中で動作中。利用者が「このセッションは payments 移行って名前にして」「これ foo でやろう」「新しく bar を始めよう」のいずれかを言う
  経路     :
    1. スキル `skills/tower` のトリガー表で意図を判定する
    2. 「続ける」なら要約を型(目的・決めたこと・次にやること・参照ファイル)で書く
    3. 対応する `tower` コマンドを非対話で実行する
    4. 標準出力の id を利用者に報告し、Navigator で確認できることを伝える
  完了     : 利用者が何もコマンドを打たずに、意図どおりの状態になっている
  得る価値 : 「チャットの中から」Tower が操作できる
  関連要求 : REQ-001-013, REQ-001-014, REQ-001-016
  検証区分 : 機械判定可(スキル文面の構造) + 判断(実機 1 往復)
  優先度   : 中核

UF-001-006: 間違った指定で失敗し、原因を読んでやり直す
  利用者型 : Tower の外の iwase / 代理の Claude
  前提     : 通常のシェル、または打ち間違えたディレクトリ名
  経路     :
    1. `tower rename foo` を Tower の外で実行する → 「`--session <id>` が必要」で終了コード 2
    2. `tower open ~/working/typo` を実行する → 「ディレクトリが無い」で終了コード 1、セッションは作られない
    3. `tower project new bar` を既存名で実行する → 「既に存在する」で終了コード 1、何も触られない
    4. 文言(と必要なら `tower help`)を読んで正しい指定でやり直す
  完了     : 失敗ごとに原因が区別でき、副作用が残っていない
  得る価値 : 失敗しても状態が壊れず、何を直せばよいか分かる
  関連要求 : REQ-001-015, REQ-001-020, REQ-001-021, REQ-001-022, REQ-001-023, REQ-001-024, REQ-001-025, REQ-001-026, REQ-001-027, REQ-001-029
  検証区分 : 機械判定可
  優先度   : 重要
