## 機能要求 — rename(E-001, E-002, E-004)

REQ-001-001 [Event-driven]
利用者が `tower rename <name>` を実行したとき、システムは対象セッションの
metadata の `session_name` を `<name>` に書き換えなければならない。

  由来: VH-001 / UF-001-001 / E-001
  検証: 受入シナリオ (機械判定可)
  優先: 必須

REQ-001-002 [State-driven]
`--session` が指定されていない間、システムは呼び出し元の pane が属する
Tower セッション(`TMUX_PANE` から解決)を対象としなければならない。

  由来: VH-001 / UF-001-001 / E-002
  検証: 受入シナリオ (機械判定可)
  優先: 必須

REQ-001-003 [Ubiquitous]
システムは常に、rename による metadata の書き換えで `created_at` /
`launch_dir` / `live_id` の値を変えてはならず、書き換えは一時ファイルへの
書き出しと `mv` による置換で行わなければならない。

  由来: VH-001 / E-003(再構築が途中状態を読まない)
  検証: 単体テスト (機械判定可)
  優先: 必須

REQ-001-004 [Event-driven]
利用者が `tower rename --clear` を実行したとき、システムは対象セッションの
`session_name` を削除し、表示を最初のプロンプト由来の題名に戻さなければ
ならない。

  由来: E-004 / UF-001-002
  検証: 単体テスト (機械判定可)
  優先: 任意

REQ-001-005 [State-driven]
Navigator が動作している間、システムは rename 後の次回再構築で新しい名前を
行に表示しなければならない。

  由来: VH-001 / E-003 / UF-001-001
  検証: 受入シナリオ (機械判定可)
  優先: 必須

## 機能要求 — open(E-005, E-006, E-007)

REQ-001-006 [Event-driven]
利用者が `tower open <dir>` を実行したとき、システムは `<dir>` を作業
ディレクトリとする新しい Tower セッションを開始し、その metadata に
`launch_dir=<dir>` を記録しなければならない。

  由来: VH-002 / UF-001-003 / E-005
  検証: 受入シナリオ (機械判定可)
  優先: 必須

REQ-001-007 [Event-driven]
利用者が `--prompt <text>` または `--prompt-file <path>`(`-` は標準入力)を
付けて `tower open` を実行したとき、システムはその文字列を新セッションの
claude の最初のプロンプトとして渡さなければならない。

  由来: VH-002 / UF-001-003 / E-006
  検証: 受入シナリオ (機械判定可: 起動コマンド行にプロンプトファイルの参照が含まれ、ファイル内容が渡した文字列と一致する)
  優先: 必須

REQ-001-008 [Event-driven]
`tower open` が新セッションの開始に成功したとき、システムは Navigator の
選択(`selected` 状態ファイル)を新セッションに移さなければならない。

  由来: VH-002 / UF-001-003 / E-005
  検証: 受入シナリオ (機械判定可)
  優先: 必須

REQ-001-009 [State-driven]
Navigator サーバが動作している間、`tower open` の成功後にシステムは
Navigator の view pane を新セッションへ切り替えなければならない。

  由来: E-007 / UF-001-003
  検証: 結合テスト (機械判定可: view pane の client が新セッションに付いている)
  優先: 任意

REQ-001-010 [Ubiquitous]
システムは常に、`tower open` で元のセッション(呼び出し元)を終了・休眠・
変更してはならない。

  由来: orient.md 非スコープ / UF-001-003
  検証: 受入シナリオ (機械判定可)
  優先: 必須

## 機能要求 — project new(E-008)

REQ-001-011 [Event-driven]
利用者が `tower project new <name>` を実行したとき、システムは
`<parent>/<name>`(`<parent>` は `--in` の値、未指定なら `~/working`)を
作成し、`git init` を実行し、そのディレクトリで新しい Tower セッションを
開始しなければならない。

  由来: VH-003 / UF-001-004 / E-008
  検証: 受入シナリオ (機械判定可)
  優先: 必須

REQ-001-012 [Event-driven]
利用者が `tower project new` に `--prompt` / `--prompt-file` を付けたとき、
システムは REQ-001-007 と同じ方法で最初のプロンプトを渡さなければならない。

  由来: VH-003 / UF-001-004
  検証: 単体テスト (機械判定可)
  優先: 必須

## 機能要求 — CLI 契約(E-010, E-011, E-013, E-014)

REQ-001-013 [Event-driven]
`rename` / `open` / `project new` が成功したとき、システムは対象セッションの
id(`tower_<uuid>`)だけを標準出力に 1 行で出力し、人向けの文言は標準
エラー出力に出さなければならない。

  由来: E-010 / UF-001-005
  検証: 単体テスト (機械判定可)
  優先: 必須

REQ-001-014 [Ubiquitous]
システムは常に、標準入力が端末でないときに対話的な確認を出さずに完走
しなければならない。

  由来: E-014 / UF-001-005
  検証: 単体テスト (機械判定可)
  優先: 必須

REQ-001-015 [Ubiquitous]
システムは常に、`tower help` の出力に `rename` / `open` / `project new` の
書式と 1 行説明を含めなければならない。

  由来: E-013
  検証: 単体テスト (機械判定可)
  優先: 任意

## 機能要求 — スキル(E-012)

REQ-001-016 [Ubiquitous]
システムは常に、`skills/tower/SKILL.md` に次を含めなければならない:
3 つの意図(名前を変える / 別プロジェクトで続ける / 新しいプロジェクトを
始める)それぞれのトリガー語と対応するコマンド、引き継ぎ要約の型
(目的・これまでに決めたこと・次にやること・参照ファイル)、
成功時に標準出力の id を利用者へ報告する手順。

  由来: VH-002 / E-012 / UF-001-005
  検証: 単体テスト (機械判定可: 見出しとコマンド名の存在) + 実機 1 往復 (判断)
  優先: 必須

## 異常系要求

REQ-001-020 [Unwanted]
もし `--session` なしの rename が Tower セッションの pane の外(`TMUX_PANE`
が無い、または Tower のセッションサーバに属さない)で実行されたならば、
システムは「Tower セッションの外では `--session <id>` が必要」と標準
エラー出力に示し、終了コード 2 で終了しなければならない。

  由来: E-002 / E-011 / UF-001-006
  検証: 受入シナリオ (機械判定可)
  優先: 必須

REQ-001-021 [Unwanted]
もし rename の `<name>` が空、または `--clear` と同時に指定されたならば、
システムは metadata を変更せず、理由を標準エラー出力に示し、終了コード 2
で終了しなければならない。

  由来: E-011
  検証: 単体テスト (機械判定可)
  優先: 必須

REQ-001-022 [Unwanted]
もし `--session <id>` の metadata が存在しないならば、システムは
「セッション `<id>` は登録されていない」と示し、終了コード 1 で終了
しなければならない。

  由来: E-011
  検証: 単体テスト (機械判定可)
  優先: 必須

REQ-001-023 [Unwanted]
もし `tower open <dir>` の `<dir>` が存在しない、またはディレクトリで
ないならば、システムはセッションを作らず、「ディレクトリが無い: <dir>」と
示し、終了コード 1 で終了しなければならない。

  由来: E-011 / UF-001-006
  検証: 受入シナリオ (機械判定可)
  優先: 必須

REQ-001-024 [Unwanted]
もし `--prompt-file <path>` が読めないならば、システムはセッションを作らず、
理由を示し、終了コード 1 で終了しなければならない。

  由来: E-011
  検証: 単体テスト (機械判定可)
  優先: 必須

REQ-001-029 [Unwanted]
もし渡されたプロンプトが空白のみ、または 100 KiB(`PROMPT_MAX_BYTES`)を
超えるならば、システムはセッションを作らず、理由を示し、終了コード 1 で
終了しなければならない。

  由来: E-006 / E-011(レビュー指摘: 空の位置引数と MAX_ARG_STRLEN 超過)
  検証: 単体テスト + 受入シナリオ (機械判定可)
  優先: 必須

REQ-001-025 [Unwanted]
もし `tower project new <name>` の作成先が既に存在するならば、システムは
ディレクトリにも git にも触れず、「既に存在する: <path>」と示し、終了
コード 1 で終了しなければならない。

  由来: E-011 / UF-001-006
  検証: 受入シナリオ (機械判定可)
  優先: 必須

REQ-001-026 [Unwanted]
もし `tower project new` の `<name>` にパス区切り(`/`)が含まれる、または
先頭が `-` か `.` であるならば、システムは何も作らず、理由を示し、終了
コード 2 で終了しなければならない。

  由来: E-011
  検証: 単体テスト (機械判定可)
  優先: 必須

REQ-001-027 [Unwanted]
もし `tower project new` で `git init` が失敗したならば、システムは
セッションを開始せず、作成したディレクトリをそのまま残して失敗理由を示し、
終了コード 1 で終了しなければならない。

  由来: E-011
  検証: 単体テスト (機械判定可)
  優先: 必須

REQ-001-028 [Unwanted]
もし Navigator サーバが動作していないならば、`tower open` はセッションの
開始と `selected` の更新を行い、view の切り替えは省略して成功として
終了しなければならない。

  由来: E-007 / UF-001-003
  検証: 受入シナリオ (機械判定可)
  優先: 必須
