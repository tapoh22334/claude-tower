# r による休眠セッションの起動 — 要求

feature-id: 004-nav-r-start
由来: value/004-nav-r-start/orient.md

## 機能要求

REQ-004-001 [Event-driven]
利用者が休眠中(○)のセッションの行で r を押したとき、システムはそのセッションを起動し、行を ◐ で描かなければならない。このとき焦点は一覧に残さなければならない。
  由来: VH-001 / UF-004-001
  検証: 受入シナリオ (機械判定可)
  優先: 必須

REQ-004-002 [Event-driven]
利用者がプロジェクトの見出しの行で r を押したとき、システムはそのプロジェクトの休眠中のセッションをすべて起動し、起動した各行を ◐ で描かなければならない。
  由来: VH-002 / UF-004-002
  検証: 受入シナリオ (機械判定可)
  優先: 必須

REQ-004-003 [Event-driven]
利用者が見出しの行で r を押して 1 本以上が起動したとき、システムは起動した本数を一覧の下に表示しなければならない。
  由来: VH-002 / UF-004-002
  検証: 受入シナリオ (機械判定可)
  優先: 必須

REQ-004-004 [Ubiquitous]
システムは常に、r で起動するかどうかを Enter による再開と同じ条件(tmux セッションがなく、登録されていて、別の場所で動作中でなく、会話の記録とディレクトリが残っている)で決めなければならない。
  由来: VH-001, VH-002
  検証: 受入シナリオ (機械判定可)
  優先: 必須

REQ-004-005 [Ubiquitous]
システムは常に、ヘルプに r の行を表示しなければならない。
  由来: VH-001
  検証: 受入シナリオ (機械判定可)
  優先: 必須

## 異常系要求

REQ-004-010 [Unwanted]
もし r を押した行が起動中・別の場所で動作中(◇)・復元できない(✗/?)のいずれかならば、システムはセッションを起動せず、その理由を一覧の下に表示しなければならない。
  由来: VH-001
  検証: 受入シナリオ (機械判定可)
  優先: 必須

REQ-004-011 [Unwanted]
もし見出しの行で r を押したときに、そのプロジェクトに休眠中のセッションが 1 本もないならば、システムは何も起動せず、休眠中のセッションがないことを一覧の下に表示しなければならない。
  由来: VH-002
  検証: 受入シナリオ (機械判定可)
  優先: 必須

REQ-004-012 [Unwanted]
もしセッションの起動に失敗したならば、システムはその行を ○ のまま残し、失敗した本数を一覧の下に表示しなければならない。
  由来: VH-001, VH-002
  検証: 受入シナリオ (機械判定可)
  優先: 必須

REQ-004-013 [Unwanted]
もし selected ファイルの行と画面の行が一致しないならば、システムはセッションを起動してはならない。
  由来: VH-001
  検証: 受入シナリオ (機械判定可)
  優先: 必須

## 矛盾点検の記録

| 組 | 衝突の内容 | 判断 | 根拠 |
|---|---|---|---|
| REQ-004-001 と 003 の REQ(Enter と D だけが行の種類で意味を変える) | r は見出しの行とセッション行で対象が変わる | r を「カーソルの下にある休眠中のセッションを起動する」と定義し、どちらの行でも同じ意味とする | 見出しの行の「下にある」のは、そのプロジェクトのセッションである。deviations.md に記録した |
| REQ-004-013 と REQ-004-002 | 一括起動では、選択している行は見出しの行である | 一致の検査は、見出しの行の id(`dir:<path>`)で行う | 003 の逸脱 7 と同じ保護を見出しの行にも適用する |
