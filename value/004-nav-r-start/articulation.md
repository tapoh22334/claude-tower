# r による休眠セッションの起動 — 分節

feature-id: 004-nav-r-start
由来: value/004-nav-r-start/orient.md

> 適用範囲は**利用者との境界面**。内部設計は対象外(構築層が扱う)。

## 境界面の要素

| ID | 要素 | 説明 |
|---|---|---|
| E-001 | セッション行の r | 休眠中のセッションを起動し、焦点は一覧に残す |
| E-002 | 見出しの行の r | そのプロジェクトの休眠中のセッションをすべて起動する |
| E-003 | 起動中の行の表示 | 起動した行を、次の再構築を待たずに ◐ で描く |
| E-004 | 起動できないときの理由 | 起動するものがない・起動に失敗したときに一覧の下へ出す 1 行 |
| E-005 | ヘルプとフッターの案内 | ヘルプに r の 1 行を足す。フッターは 80 桁の制約があるので足さない |
| E-006 | 一括起動前の確認 | 見出しの行の r で、起動する本数を示して y/n を問う |

## 第1段: 実装を括弧に入れる

| ID | 完全技術でも残るか | 残らないなら何の回避策か |
|---|---|---|
| E-001 | 残る | |
| E-002 | 残る | |
| E-003 | 残らない | 再構築に 1 秒以上かかることの回避策。即時に状態が分かれば不要である |
| E-004 | 残る | |
| E-005 | 残る | |
| E-006 | 残らない | 起動の取り消しの手間が大きいことの回避策。起動は D で消せるので、取り消しの手間は小さい |

## 第2段: 文脈と不適合から本体を定義

### misfit 列挙(際立つ順)

1. **起動のたびに焦点が移る** — 応える要素: E-001
2. **本数だけ同じ操作を繰り返す** — 応える要素: E-002
3. **押しても何も起きないと、壊れたと判断する** — 応える要素: E-003, E-004

### breakdown の想像

| ID | これが壊れたとき、利用者は何に気づくか |
|---|---|
| E-001 | r の後に入力欄へ移ってしまい、次の行を起動するために一覧へ戻る |
| E-002 | 見出しの行で r を押しても何も起動せず、行ごとに押し直す |
| E-003 | 行が ○ のまま 1〜2 秒残り、もう一度 r を押す |
| E-004 | 起動中の行や ◇ の行で r を押して何も起きず、理由が分からない |
| E-005 | r の存在に気づかない |

### purpose / operational principle

| ID | purpose(何のため) | operational principle(どう働いて目的を果たすか) |
|---|---|---|
| E-001 | 起動と入力を分ける | 起動だけをし、焦点と選択は動かさない |
| E-002 | まとめて起動する | 見出しの行の下にある休眠中の行を順に起動する |
| E-003 | 起動を即座に確かめる | 起動した行を ◐ で描き直す |
| E-004 | 何も起きない理由を示す | 状態ごとの理由を 1 行で出す |

## 第3段: 変化させて不変を取り出す

| ID | 無くす | 弱める | 強める | 判定 |
|---|---|---|---|---|
| E-001 | 機能自体が成り立たない | 焦点が移るなら Enter と同じになる | 起動後に次の休眠行へ移動する案は、利用者が選んだ行を動かす | 不変核 |
| E-002 | 追加要望そのものが消える | 先頭の 1 本だけ起動すると要望に合わない | 全プロジェクトの起動は非スコープ | 不変核 |
| E-003 | 二度押しを招く(003 の実績) | ◐ が遅れても起動はする | アニメーションは不要 | 不変核 |
| E-004 | 「壊れた」と判断される(今回の報告) | 文言が短くても理由は伝わる | 詳細なダイアログは過剰 | 不変核 |
| E-005 | ヘルプを見る人だけが困る | フッターに無くてもヘルプにあれば足りる | 無関心 | 無関心 |
| E-006 | 誤って押しても D で消せる | 無関心 | 毎回 y を押す手間が増える | 除去可 |

## 第4段: 関節で切る

### 変わりやすい設計判断

1. 「起動してよい行」の条件(休眠中のみか、◇ も取り込むか)
2. 一括起動の範囲(プロジェクト単位か、全体か)

### 切断の妥当性

| 切断面 | 自然な関節か | 根拠 |
|---|---|---|
| 1 行の起動と、その繰り返しとしての一括起動 | 関節 | 一括起動は、見出しの下の行に 1 行の起動を適用する操作である |
| 起動の可否の判定を Enter と共有する | 関節 | 判定が分かれると、Enter で起動する行と r で起動する行が一致しなくなる |

## 第5段: 中心から展開する

| ID | 全体を強めるか | 根拠 | 反証条件 |
|---|---|---|---|
| E-001 | 強める | 起動と入力を分けることが価値の中心である | 利用者が r の後に毎回 Enter を押す |
| E-002 | 強める | 追加要望そのもの | 一括起動の後に、不要なセッションの D が続く |
| E-003 | 強める | 起動の確認を即時にする | ◐ 表示のある状態で r の二度押しが観測される |
| E-004 | 強める | 「動かない」報告を防ぐ | 理由が出ても同じ報告が来る |
| E-005 | 強めない | 見つけやすさだけで、価値の本体ではない | ヘルプに r があるのに、利用者が r の存在を知らずに Enter で 1 本ずつ起動する |
| E-006 | 強めない | 起動は D で取り消せるので、確認は手間だけを増やす | 一括起動を誤って押し、D で消す操作が繰り返し観測される |

## 第6段: 分節の一致を検証

### 独立導出(3回以上、前の結果を見ずに)

| ID | 1回目 | 2回目 | 3回目 | 収束 |
|---|---|---|---|---|
| E-001 | core | core | core | 収束 |
| E-002 | core | core | core | 収束 |
| E-003 | supporting | supporting | core | ばらつき |
| E-004 | supporting | supporting | supporting | 収束 |
| E-005 | generic | generic | generic | 収束 |
| E-006 | omittable | omittable | omittable | 収束 |

ばらついた要素への対処:
- E-003 は supporting とした。既存の `_mark_session_starting` を呼び出すだけで済み、Enter による再開と同じ表示になるためである。

### misfit 検証(収束だけでは合格にしない)

| ID | 欠けたときに起きる具体的な破綻 |
|---|---|
| E-001 | 利用者は 1 本起動するたびに焦点を一覧へ戻し、5 本なら戻す操作を 5 回する |
| E-002 | 利用者は見出しの行で r を押して何も起きず、行ごとに r を押し直す |

## 分節(結論)

| ID | 要素 | タグ | 下流での扱い |
|---|---|---|---|
| E-001 | セッション行の r | core | E2E 必須 |
| E-002 | 見出しの行の r | core | E2E 必須 |
| E-003 | 起動中の行の表示 | supporting | E2E で ◐ を確かめる |
| E-004 | 起動できないときの理由 | supporting | E2E で理由の文言を確かめる |
| E-005 | ヘルプとフッターの案内 | generic | 既存の型どおり |
| E-006 | 一括起動前の確認 | omittable | **非スコープへ** |

### omittable の送り先

- E-006: 起動は D で取り消せる。毎回の y/n は手間だけを増やす(第3段)

### 造り込みの方針

| タグ | 件数 | 方針 |
|---|---|---|
| core | 2 | 受入シナリオで実 tmux を使って確かめる |
| supporting | 2 | 受入シナリオで表示と文言を確かめる |
| generic | 1 | ヘルプの既存テストに足す |
| omittable | 1 | 作らない |
