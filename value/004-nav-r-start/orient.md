# r による休眠セッションの起動 — 方向付け

feature-id: 004-nav-r-start
日付: 2026-11-11
チケット: #128

## 解こうとしている問題

作業を再開するとき、利用者は同じプロジェクトの休眠中のセッションを何本も起動したい。しかし Navigator で起動できる操作は Enter だけである。Enter は起動と同時に焦点をセッションへ移すので、1 本起動するたびに一覧へ戻る操作が要る。003-nav-keys で `r` を削除したため、利用者が `r` を押しても何も起きない。

想定利用者:
- 1 つのプロジェクトで並行して 3〜10 本のセッションを使い分け、翌日にまとめて再開する利用者(このリポジトリの利用者本人)

今どうしているか:
- 行ごとに Enter で起動し、焦点を一覧へ戻す。これを本数だけ繰り返す。`r` を押して何も起きず、壊れたと判断した(2026-11-11 の報告)

## 作らない選択肢

### 案1: 何もしない
棄却理由: 利用者が「r ボタンによる起動が動作しない」と報告している。起動のたびに焦点が移り一覧へ戻す操作は、本数に比例して増える。

### 案2: Enter で代用する
棄却理由: Enter は「このセッションに入力する」操作で、焦点の移動が主な働きである。複数を起動する用途では、移動が毎回の余分な操作になる。

### 案3: CLI(`tower` コマンド)でまとめて起動する
棄却理由: `session-restore.sh` は引数なしのとき tmux のメニューで 1 本ずつ選ばせる。プロジェクト単位の一括起動はない。また、一覧を見ながら起動したいという要望に対し、別の端末へ移る手間が増える。

## 価値仮説

```
VH-001: 休眠中のセッションを、一覧から移らずに起動できる
  誰が    : 休眠中のセッションを複数起動したい利用者
  いつ    : 一覧で休眠中の行を選んでいるとき
  今は    : Enter で起動するたびに焦点が移り、一覧へ戻る操作が要る
  これで  : r で起動し、焦点は一覧に残る
  その結果: 次の行へそのまま移って続けて起動できる
  外れ判定: 利用者が r の後に毎回 Enter も押す(起動と入力を分ける必要がなかった)
```

```
VH-002: プロジェクト単位で、休眠中のセッションをまとめて起動できる
  誰が    : 1 つのプロジェクトのセッションをまとめて再開したい利用者
  いつ    : プロジェクトの見出しの行を選んでいるとき
  今は    : 行ごとに起動する操作を本数だけ繰り返す
  これで  : 見出しの行で r を 1 回押す
  その結果: そのプロジェクトの休眠中のセッションがすべて起動する
  外れ判定: 一括起動した後に、不要なセッションを停止する操作が続く(全部ではなく一部を起動したかった)
```

## 価値の検証可能性

| 仮説 | 区分 | 受入での扱い |
|---|---|---|
| VH-001 | 機械判定可 | 実 tmux で r を押し、行が ◐ になり、tmux セッションができ、焦点が一覧に残ることを確かめる |
| VH-002 | 機械判定可 | 休眠中 2 本・起動中 1 本のプロジェクトで見出しの r を押し、休眠中の 2 本だけが起動することを確かめる |

## 非スコープ

- 一括起動の前の確認(y/n)。起動は破壊的な操作ではなく、起動したセッションは D で消せる
- 複数のプロジェクトにまたがる一括起動
- 起動したセッションの停止(休眠に戻す)操作
- 別の場所で動作中(◇)のセッションを Tower に取り込む操作

## 判断

- [x] 作る / [ ] 作らない

理由: 案 1〜3 はどれも、複数を起動するときの、一覧へ戻す操作を減らせない。追加するのはキー 1 つで、セッション行の振る舞いは削除前の `r` と同じである。
