## 6. 欠陥クラスの更新

- **DEF-T5 の追記**: 新しい「値の種類」を共有状態に入れるとき、その状態の全読者を列挙する。
  今回は `dir:` を `selected` に入れたが、`nav_redirect_view` が tmux の前方一致で別セッションに
  当たる経路を見落とした。
- **新規 DEF-T11**: 「タイマーの条件が周期ではなく区間になっている」(`SECONDS % 2 == 0` は
  1 秒間ずっと真)。ポーリングループの再描画条件は「前回からの経過」で書く。
- **DEF-T2 の追記(ツール起因)**: pipefail + `grep -q` の SIGPIPE。bats で `--trace` を付けると
  通る失敗はこれを疑う(memory: pipefail-grep-q-sigpipe)。

## 7. パイプライン自体への改善

- vf-userflows の漏れ点検「並行」に「別プロセスが共有状態を書く」を加えた(001 の retro の
  対策)。今回 `tower project rm` と再同期の衝突を**要求(REQ-002-009)には書けたが実装で漏れた**。
  観点は正しく、実装側のチェックリスト(harness の禁止事項の適用範囲)が弱かった。
- 既存テストの前提更新 13 本は、1 本ずつ「前提の更新か回帰か」を判定して逸脱報告に書いた。
  この手順は有効で、更新で薄くなったテストは無いとレビューが確認した。
- 001 と同じ 3 点(vf-trace の引数記述、vf-construct のアダプタ不在、失敗経路のタグ規約)は
  未対応のまま。skill-improver の対象。
