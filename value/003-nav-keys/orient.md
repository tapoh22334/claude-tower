# Navigator のキーを整理し、copy とラベルジャンプを足す — 方向付け

feature-id: 003-nav-keys
日付: 2026-11-03
チケット: #102(キー整理)、#103(copy)、#104(ラベルジャンプ)

## 解こうとしている問題

Navigator のキーは 19 個ある。そのうち、選択中の行を対象にする操作は Enter / D / r の 3 つだけである。残りはどの行で押しても意味が同じか、別のキーと重複している。この状態が次の 3 つの形で表れる。

- 行の種類によって、同じキーの意味が変わる。`a` はセッション行では「取り込みか新規作成」、見出しの行では「このプロジェクトで新規作成」になる。
- 名前と中身が合わないキーがある。`f`("fork")は会話が空の新しいセッションを始めるだけで、会話を引き継がない。会話を引き継いで分岐させる手段は無い。
- 一覧が長いと、目的の行まで j/k を何度も押すか、`/` で文字を打つ必要がある。

想定利用者:

- iwase。10 前後のプロジェクトを並行し、一覧には 40 行前後が並ぶ。
- 長い会話の途中で、別の方針を試したくなることがある。今の会話を捨てずに試したい。

今どうしているか:

- 会話を分岐させるには、端末で `claude --resume <id> --fork-session` を手で打つ。こうして作ったセッションは Tower の外に置かれ、一覧には `◇` として現れるだけである。
- 離れた行へは、j/k を連打するか `/` で検索している。

## 作らない選択肢

### 案1: 何もしない

棄却理由: `f` の名前は誤解を招く。利用者は実際に「fork が正常に動いていないのか」と尋ねた。会話の分岐は Tower の外で手作業になる。作ったセッションも Tower の管理外に置かれる。

### 案2: 既存のもので代用する(`/` 検索だけで移動し、分岐は手で起動する)

棄却理由: `/` は行の文字を覚えていないと使えない。一覧の「上から 3 番目のプロジェクト」のような位置で移動する手段にはならない。分岐を手で起動しても、Tower に登録されない問題は残る。

### 案3: 問題の方を変える(ヘルプの記述を直すだけにする)

棄却理由: `f` の説明を「同じディレクトリで新規作成」に直しても、見出しの行の Enter との重複は残る。キーの数も減らない。会話を分岐させたいという要求にも答えられない。

```

  誰が    : 一覧を眺めて操作する iwase
  いつ    : セッション行と見出しの行を行き来しながら操作するとき
  今は    : `a` の意味が行の種類で変わる。`f` と `A` が見出しの行の操作と重複している
  これで  : 行の種類で意味が変わるキーが Enter と D の 2 つになる
  その結果: 重複していた 4 個(i / r / A / 旧 f)が無くなる。copy と新しい f を
            足しても、キーは 19 個から 17 個に減る
  外れ判定: 利用者が削ったキー(i / r / A)を押し続け、別名として戻すよう求める
  判定結果: `i` について外れた(#106)。利用者は `i` を Enter の別名として戻すよう求めた。
            `r` と `A` については外れていない。`i` は Enter と同じ意味なので、行の種類で
            意味が変わるキーを減らすという本体は崩れない。キーは 18 個になった
```

```
  いつ    : 離れたプロジェクトやセッションへ移りたいとき
```

## 価値の検証可能性

| 仮説 | 区分 | 受入での扱い |
|---|---|---|
| VH-001 | 機械判定可 | 各キーをセッション行と見出しの行で押し、Enter と D 以外は同じ処理を呼ぶことを確かめる。ヘルプとフッターの一覧がキーの処理と一致することを確かめる |
| VH-002 | 機械判定可 | `c` で起動するコマンドが `--resume <元> --fork-session --session-id <新>` であり、新しい id がメタデータに登録されることを確かめる。実際の claude での複製は手で 1 回確かめる |
| VH-003 | 機械判定可 | `f` `c` `b` の打鍵で、選択が 3 番目のプロジェクトの先頭セッションに移ることを確かめる(#106 で `f` `c` `a` から改訂) |

「判断必要」に分類したものの分解を試みた記録:

- VH-003 の「ラベルが読みやすいか」は判断必要である。受入では「ラベルが行の左に出て、1 文字目を押すと対象のグループだけが残る」に分解する。読みやすさは使ってから判断する。

## 非スコープ

**今回作らないもの。** 構築契約の I6 としてそのまま渡る。

- Tile / Tail / Queue 表示の中のキーを揃えること。一覧のキーが決まってから揃える。
- 削ったキー(`r` / `A` / 旧 `f`)の別名や、押されたときの移行案内。`i` は #106 で Enter と同じ操作として戻した。
- 27 個以上のプロジェクトや、プロジェクト内の 27 個以上のセッションへのラベル。a〜z を使い切ったら、それ以降の行にはラベルを付けない。
- 画面外にはみ出した行へジャンプしたときの表示位置。一覧が画面に収まらないときの表示は #83 で扱う。
- 複製を一覧で元のセッションの下に並べること。fork の親子の表示は #26 で扱う。
- E-011 削ったキーを押したときの案内: 第3段で除去可と判定した(vf-articulate)。無反応でもヘルプを見れば分かり、古いキーに意味を残すと整理に逆行する。
- E-012 復旧できないグループのラベル: 第3段で除去可と判定した(vf-articulate)。復旧できない行は D で消すだけの行で、飛ぶ先として使わない。
- E-013 27 個目以降のラベル: 第3段で除去可と判定した(vf-articulate)。想定の一覧の規模では 26 に届かない。

## 判断

- [x] 作る / [ ] 作らない

理由: 3 つの作らない選択肢は、いずれも「名前と中身のずれ」と「会話の分岐が Tower の外になる」を解消しない。キーの整理は、copy と新しい `f` に場所を空けるためにも必要である。3 つの価値仮説は、すべて機械判定に落とせる。
