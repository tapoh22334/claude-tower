# Navigator のキーを整理し、copy とラベルジャンプを足す — 分節

feature-id: 003-nav-keys
由来: value/003-nav-keys/orient.md

> 適用範囲は**利用者との境界面**である。内部設計は対象外である(構築層の仕事)。
> `lint-articulation.py` が形式を検査する。

## 境界面の要素

| ID | 要素 | 説明 |
|---|---|---|
| E-001 | 行の Enter | 動いているセッションなら入力欄へ移る。休眠中なら再開してから移る。見出しの行なら、そのプロジェクトで新しいセッションを始める |
| E-002 | 行の D | セッションを消す。見出しの行なら、プロジェクトを一覧から外す |
| E-003 | `a` の既定ディレクトリ | 新しいセッションの場所の初期値を、カーソルの行のプロジェクトにする |
| E-004 | `c` の複製 | セッション行で押すと、会話を引き継いだ複製を同じディレクトリに登録し、起動する |
| E-005 | 複製の名前 | 元の名前に ` copy` を付ける。元に名前が無ければ `copy` にする |
| E-006 | 複製を断る理由の表示 | 会話の記録が無い行や外部のセッションでは複製せず、理由を出す |
| E-007 | `f` の 2 段のラベル | 見出しの行に a, b, c…、セッション行に見出しのラベルと自分のラベルを並べて出す |
| E-008 | 1 文字目でグループを絞る | 1 文字目を押すと、そのプロジェクトのラベルだけが残る |
| E-009 | Enter で見出しへ、Esc で取り消し | 1 文字目の後の Enter は見出しの行へ移る。Esc や割り当ての無いキーはジャンプをやめる |
| E-010 | ヘルプとフッターの一覧 | 表示するキーの一覧が、実際のキーの処理と一致する |
| E-011 | 削ったキーを押したときの案内 | `i` / `r` / `A` を押したときに、代わりのキーを知らせる |
| E-012 | 復旧できないグループのラベル | `── unrecoverable ──` の下の行にもラベルを付ける |
| E-013 | 27 個目以降のラベル | a〜z を使い切った後の行にも 2 文字のラベルを付ける |

## 第2段: 文脈と不適合から本体を定義

### misfit 列挙(際立つ順)

1. **`f` が会話を引き継がないのに "fork" と名乗る** — 利用者は「fork が正常に動いていないのか」と尋ねた。会話を分岐させるには Tower の外で手作業になる。応える要素: E-004
2. **離れた行へ移るのに j/k の連打か文字入力が要る** — 40 行前後の一覧では、位置で指す手段が無い。応える要素: E-007, E-008
3. **行の種類で同じキーの意味が変わり、重複するキーが 4 つある** — `a` / `f` / `A` が見出しの行の Enter と重なる。応える要素: E-001, E-003, E-010
4. **休眠中の行を使うのに `r` と Enter の 2 つを覚える必要がある** — 応える要素: E-001

### breakdown の想像

| ID | これが壊れたとき、利用者は何に気づくか |
|---|---|
| E-001 | 休眠中の行で Enter を押しても何も起きず、再開の手段が分からなくなる |
| E-002 | 不要な行を消せず、一覧が膨らむ |
| E-003 | `a` の場所の候補が呼び出し元のディレクトリになり、毎回選び直す |
| E-004 | 分岐のたびに端末で `claude --resume` を打つ作業に戻る |
| E-005 | 一覧に同じ名前が 2 行並び、どちらが元か分からない |
| E-006 | `c` を押しても何も起きず、壊れたのか断られたのか区別できない |
| E-007 | `f` を押しても行の左に何も出ず、どのキーで飛ぶか分からない |
| E-008 | 1 文字目の後も全部のラベルが残り、2 文字目を探す視線が散る |
| E-009 | 見出しの行へ飛べない。押し間違えたときに抜けられない |
| E-010 | ヘルプに載っているキーが動かない、または動くキーが載っていない |
| E-011 | 古いキーを押しても無反応で、少し戸惑う |
| E-012 | 復旧できない行へはラベルで飛べず、j/k で移る |
| E-013 | 27 個目以降の行へはラベルで飛べず、j/k で移る |

### purpose / operational principle

| ID | purpose(何のため) | operational principle(どう働いて目的を果たすか) |
|---|---|---|
| E-001 | 行を使う操作を 1 つのキーにまとめる | 行の状態(動いている・休眠中・見出し)を見て、使える状態にしてから入力欄へ移す |
| E-002 | 行を一覧から取り除く | 確認を求めてから消す |
| E-003 | 新しいセッションを、今見ているプロジェクトに作る | カーソルの行が属するプロジェクトを、場所の候補の先頭に置く |
| E-004 | 会話を捨てずに別の方針を試す | 元の会話を新しい id で再開させ、Tower に登録する |
| E-005 | 複製と元を一覧で見分ける | 元の名前に印を付ける |
| E-006 | 複製できない理由を知らせる | 複製の前に会話の記録の有無を調べ、無ければ理由を出して止める |
| E-007 | どの行へも位置で飛ぶ | 見出しとセッションに、上から順に文字を割り当てて行の左に出す |
| E-008 | 2 文字目を探す範囲を狭める | 1 文字目に一致しないラベルを消す |
| E-009 | 見出しへの移動と、やめる手段を用意する | 1 文字目の後の Enter と Esc に、それぞれ意味を割り当てる |
| E-010 | 操作をヘルプから学べるようにする | キーの一覧を 1 か所で持ち、ヘルプとフッターに同じものを出す |
| E-011 | 古いキーからの移行を助ける | 削ったキーを押すと、代わりのキーを一時的に出す |
| E-012 | 復旧できない行にも位置で飛ぶ | 復旧できないグループを 1 つのプロジェクトとして扱い、ラベルを振る |
| E-013 | 26 を超える行にも位置で飛ぶ | 2 文字のラベルに広げる |

## 第3段: 変化させて不変を取り出す

狩野の対質問(「無かったらどう感じるか」)を各行で併用した。

| ID | 無くす | 弱める | 強める | 判定 |
|---|---|---|---|---|
| E-001 | 休眠中の行を使う手段が消え、`r` を削れなくなる。整理が成立しない | 再開だけして入力欄へ移らなくても、もう 1 回 Enter で済む | 再開後に入力欄へ移る速さが倍でも気づかない | 不変核 |
| E-002 | 消す手段が無くなる。無いと困る | 確認を省いても成立するが危ない | 気づかない | 不変核 |
| E-003 | 毎回場所を選び直すことになり、不満が出る | 呼び出し元の場所でも作れはする | 気づかない | 無関心 |
| E-004 | 依頼の 1 番目が満たされない。無いと強く不満 | 起動に時間がかかっても成立する | 複数の複製を一度に作れても使わない | 不変核 |
| E-005 | 同じ名前が並んでも、後から名前を変えれば済む | 印が短くても見分けられる | 番号を付けても嬉しくない | 無関心 |

| E-008 | 全部残っても飛べはするが、2 文字目を探しにくい | 残ったラベルを強調しなくても読める | 気づかない | 不変核 |
| E-009 | 見出しへ飛べず、押し間違えから抜けられない | Esc だけあれば抜けられる | 気づかない | 不変核 |

## 第4段: 関節で切る

### 変わりやすい設計判断

1. ラベルの文字の並び(a〜z か、ホームポジションの文字を先にするか)
2. 複製の名前の付け方
3. 行の種類ごとの Enter の意味(休眠中の行で再開まで自動でするか)
4. どのキーをどの機能に割り当てるか

### 切断の妥当性

| 切断面 | 自然な関節か | 根拠 |
|---|---|---|
| キーの割り当て(E-001〜E-003, E-010)と各機能の中身 | 関節 | 割り当ては 1 か所の分岐で決まる。キーを差し替えても機能の中身は変わらない |
| ラベルの付け方(E-007)と、押した後の振る舞い(E-008, E-009) | 関節 | 文字の並びを変えても、絞り込みと取り消しの規則はそのまま使える |
| 複製の起動(E-004)と名前・断り方(E-005, E-006) | 関節 | 名前の規則も断る条件も、起動の方法と独立に変えられる |

## 第5段: 中心から展開する

core は E-001, E-004, E-007 である。

| ID | 全体を強めるか | 根拠 | 反証条件 |
|---|---|---|---|
| E-001 | 強める | Enter が休眠中の行も扱うことで、`r` と `i` を削れる。整理の中心になる | 休眠中の行で Enter を押したのに再開されず、利用者が `r` を探す |
| E-002 | 強める | 行への操作を Enter と D の 2 つにする整理の片側である | D を押したのにセッション行と見出しの行で意味が逆になる |
| E-003 | 強める | `A` を削っても、カーソルの位置から場所を選べる | `a` の後に利用者が毎回場所を打ち直す |
| E-004 | 強める | 「fork」の名前と中身のずれを、正しく動く複製で解消する | 複製の最初の画面に、元の会話の続きが出ない |
| E-005 | 強める | 複製と元が一覧に並んだときに区別できる | 複製と元の区別がつかず、利用者が誤った行に入力する |
| E-006 | 強める | `c` が無反応になる場面を無くす | 記録の無い行で `c` を押して、何も表示されない |
| E-007 | 強める | 新しい `f` の本体で、位置で飛ぶ手段を足す | `fca` が 3 番目のプロジェクトの先頭セッション以外へ移る |
| E-008 | 強める | 2 文字目を探す範囲を 1 プロジェクトに狭め、E-007 を速くする | 1 文字目の後にも別のプロジェクトのラベルが残る |
| E-009 | 強める | 見出しへの移動と取り消しが無いと、E-007 が見出しの行へ届かない | Enter で見出しに移らない、または Esc の後もラベルが残る |
| E-010 | 強める | キーの整理を利用者が学べる形にする | ヘルプに載ったキーで、実際の処理と異なるものが 1 つでもある |
| E-011 | 強めない | 整理の目的はキーを減らすことで、古いキーに意味を残すと逆行する | 利用者が削ったキーを押し、戸惑う。その後、案内を求める |
| E-012 | 強めない | 復旧できない行は消すだけの行で、飛ぶ先にならない | 利用者が復旧できない行へラベルで飛ぼうとする |
| E-013 | 強めない | 想定の一覧の規模では 26 に届かない | 一覧のプロジェクトが 26 を超える |

## 第6段: 分節の一致を検証

### 独立導出(3回以上、前の結果を見ずに)

3 つのサブエージェントに、要素の一覧と orient.md だけを渡し、互いの結果を見せずにタグと確率を出させた。表には各回で確率が最も高いタグを書く。

| ID | 1回目 | 2回目 | 3回目 | 収束 |
|---|---|---|---|---|
| E-001 | core | generic | core | ばらつき |
| E-002 | generic | generic | supporting | ばらつき |
| E-003 | supporting | supporting | supporting | 収束 |
| E-004 | core | core | core | 収束 |
| E-005 | supporting | supporting | supporting | 収束 |
| E-006 | supporting | generic | supporting | ばらつき |
| E-007 | core | core | core | 収束 |
| E-008 | core | supporting | supporting | ばらつき |
| E-009 | supporting | supporting | supporting | 収束 |
| E-010 | supporting | generic | generic | ばらつき |
| E-011 | omittable | omittable | supporting | ばらつき |
| E-012 | omittable | omittable | omittable | 収束 |
| E-013 | omittable | omittable | supporting | ばらつき |

ばらついた要素への対処:

- E-001: core とした。2 回目は「入力欄へ移るのは当然の動き」と見て generic を付けた。しかし今回の Enter は休眠中の行の再開も引き受け、`r` と `i` を削れるかどうかがこれで決まる。第 3 段で、無くすと整理が成立しないことを確かめている。
- E-002: 多数に従い generic とした。D は既にあり、今回は意味を変えない。
- E-006: 多数に従い supporting とした。無反応だと `c` が壊れたのか断られたのか区別できない。この破綻は第 2 段に書いた。
- E-008: 多数に従い supporting とした。絞り込まなくてもジャンプはできる。
- E-010: 多数に従い generic とした。
- E-011, E-013: omittable とした。supporting を付けた 3 回目は orient.md を読んでいない。orient.md の非スコープに既に入っており、第 3 段でも除去可と判定した。
- 第 3 段で無関心とした E-003 と E-005 は、3 回とも supporting に収束した。無いと毎回の手間や取り違えが起きる点を重く見て、supporting に上げた。

### misfit 検証(収束だけでは合格にしない)

| ID | 欠けたときに起きる具体的な破綻 |
|---|---|
| E-001 | `r` を削った後、休眠中の行で Enter を押しても再開されない。利用者は休眠中のセッションを使う手段を失う |
| E-004 | 利用者は分岐のたびに端末へ戻り、`claude --resume <id> --fork-session` を手で打つ。できたセッションは `◇` として Tower の管理外に残る |
| E-007 | `f` を押しても行の左にラベルが出ない。利用者は j/k の連打に戻り、`fca` で 3 番目のプロジェクトの先頭セッションへ移れない |

### omittable の送り先

`orient.md` の非スコープへ転記する要素:

- E-011: 第3段で除去可と判定した。無反応でもヘルプを見れば分かり、古いキーに意味を残すと整理に逆行する
- E-012: 第3段で除去可と判定した。復旧できない行は D で消すだけの行で、飛ぶ先として使わない
- E-013: 第3段で除去可と判定した。想定の一覧の規模では 26 に届かない

### 造り込みの方針

| タグ | 件数 | 方針 |
|---|---|---|
| core | 3 | 受入シナリオで異常系まで確かめる。実際の claude での複製は手で 1 回確かめる |
| supporting | 5 | 正常系と主要な異常系をテストする |
| generic | 2 | 既存の型どおりに作り、テストは軽くする |
| omittable | 3 | 作らない |
