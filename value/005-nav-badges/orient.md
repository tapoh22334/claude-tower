# シェルとエージェントのバッジ — 方向付け

feature-id: 005-nav-badges
日付: 2026-11-26
チケット: #133

## 解こうとしている問題

Navigator の一覧は、バックグラウンドで動いているシェル(`run_in_background` で起動した dev サーバーやポーリング)を数えない。そのため、プログラムを動かしているセッションも待機中(空白)と表示される。利用者は、どのセッションでプログラムが動いているかを一覧から知ることができない(2026-11-25 の報告「プログラムを裏で回している状態がうまく検知されない」)。

また、右端の `⚙N` はエージェントの数を表している。歯車はプログラムを連想させるため、印の意味と見た目が合っていない。

想定利用者:
- 複数のセッションを並行して使い、そのうちいくつかで dev サーバーや長いスクリプトをバックグラウンドで動かす利用者(このリポジトリの利用者本人)

今どうしているか:
- セッションを 1 つずつ開き、Claude の画面下部の `· 1 shell` を見て確かめている

## 作らない選択肢

### 案1: 何もしない
棄却理由: 利用者が、バックグラウンドで動くプログラムを検知できないことを問題として報告している。

### 案2: 作業中には含めず、バッジだけを表示する
棄却理由: 利用者が「busy の条件にシェルのタスクも入れる」と指定した(2026-11-26)。#85 では dev サーバーが原因でスピナーが回り続けることを問題にした。しかし今回は `⚙N` で理由が表示されるので、回り続けることを仕様として受け入れる。

### 案3: Claude Code の `/tasks` などを開いて確かめる運用にする
棄却理由: セッションを 1 つずつ開く手間は今と同じで、一覧で見渡せない。

## 価値仮説

```
VH-001: バックグラウンドでプログラムが動いているセッションを、一覧で見つけられる
  誰が    : 複数のセッションで dev サーバーやスクリプトをバックグラウンドで動かす利用者
  いつ    : Navigator の一覧を見ているとき
  今は    : 待機中と同じ表示なので、セッションを開いて確かめる
  これで  : スピナーと ⚙N が付く
  その結果: 止め忘れたプログラムや、終わるのを待っている処理を、開かずに見つけられる
  外れ判定: ⚙ の付いた行を見ても、利用者がそれでもセッションを開いて確かめる
```

```
VH-002: 動いているのがエージェントかシェルかを、一覧で見分けられる
  誰が    : 同上
  いつ    : スピナーの付いた行を見ているとき
  今は    : エージェントの数だけが右端に ⚙N で表示され、シェルは表示されない
  これで  : アイコンのすぐ右に ✦N(エージェント)と ⚙N(シェル)が並ぶ
  その結果: 待てば終わる作業か、止めるかどうか判断すべきプログラムかを見分けられる
  外れ判定: 利用者が ✦ と ⚙ を取り違える
```

## 制約

- 一覧の再構築 1 回あたりの fork を増やさない(#97)。シェルの数は、すでに取得している pane の画面から読み取る。
- 右端の列の予約は残さない(利用者の指示「余計な過去の残骸を残さない」)。
- busy の行では未読(•)を表示しない。今の仕様のままとする(利用者の指示)。
